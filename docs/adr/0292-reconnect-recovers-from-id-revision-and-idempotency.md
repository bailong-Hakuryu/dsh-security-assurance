# Reconnect recovers from ID, revision, and idempotency

Refresh, overlay close, Client HMR, network interruption, and Host reconnect recover by re-deriving Security Invocation, resolving a low-sensitivity Assessment or operation ID, and fetching current Snapshot and revision from the Service. An unconfirmed mutation may be resubmitted only with its original idempotency key, producing the original Receipt or a typed conflict rather than duplicate work. Browser cache is never treated as authoritative continuation state, and disconnect never triggers a new Assessment automatically.
